# Plastic Waste Analysis

Clustering analysis of state/UT-wise plastic waste generation in India using reported data for 2016-17 to 2020-21. States/UTs are grouped by average generation level and growth trend.

## Directory contents

| File | Description |
|---|---|
| `analysis.py` | Main analysis script. Loads data, engineers features, scales, selects *k* for K-Means by silhouette score (k=2–6), fits K-Means and agglomerative clustering, saves `clusters.png`, `results.csv`, `summary.json`. |
| `run.py` | Earlier/alternative pipeline with similar logic. Writes `results.csv` and `summary.json` (summary schema differs: includes `n_states`, `best_k`, `cluster_means`). |

## Methodology

### Feature engineering
- `mean_gen` — mean of `2016-17`–`2020-21` per state/UT (pandas row mean over available years).
- `growth_pct` — percentage change from the first available year to the last available year: `(last - first) / first * 100`. If fewer than 2 yearly values are available, growth is `NaN`.

### Preprocessing
- Feature matrix: `['mean_gen', 'growth_pct']`.
- Missing feature values filled with column medians (`fillna(median)`).
- Standardized with `sklearn.preprocessing.StandardScaler`.

### Clustering
- **K-Means:** evaluated for `k` in {2..6} (`n_init=10`, `random_state=42`); best `k` chosen by highest silhouette score on the standardized features.
- **Agglomerative (hierarchical):** `sklearn.cluster.AgglomerativeClustering` with `n_clusters = best_k` (same feature space). Labels stored as `hier_cluster` (not used for `k` selection).

### Output schema (`results.csv`)
- Original columns + `mean_gen`, `growth_pct`, `kmeans_cluster`, `hier_cluster`.

## Usage

```bash

python run.py
```

**Notes:**
- Scripts use absolute paths (input CSV and outputs under `/home/roshan/Pictures/aditya ML/analysis/`). Update paths inside `analysis.py`/`run.py` to run in another environment.
- `analysis.py` sets a non-interactive Matplotlib backend (`Agg`) and saves `clusters.png`; `run.py` focuses on computing/saving `results.csv` and `summary.json`.
- `analysis.py` writes a compact `summary.json` (`n`, `k`, `silhouette`), while `run.py` writes a richer summary (`n_states`, `best_k`, `silhouette`, `cluster_means`).

## Limitations / caveats

- Small sample (35 regions) and only two clustering features; results are descriptive/exploratory.
- Missing yearly values and very small baselines can inflate `growth_pct` (e.g. cluster 1).
- No dedicated environment/lock file is included; library versions may affect numeric details (e.g. clustering with ties/initialization nuances).
- Hard-coded absolute paths reduce portability until parameterized.
